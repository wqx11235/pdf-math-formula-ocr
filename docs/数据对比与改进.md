# 数据对比与优化：三份数据、工时估算、耗时归因

> 2026-11-24。数据来自 34 本 / 199 页 / 3,808 个布局块的实际运行，不是估算。

## 一、三份数据的关系

| 数据 | 参数 | 覆盖 | 用途 |
|---|---|---|---|
| 旧基线 | workers=32 / np=1 | 199 页，628 个公式块（`dataset.csv`，已剔除 001-003 的旧模板） | 分数基线；长书会崩，不能用于全集 |
| 新重跑 | workers=4 / np=2 | 同样 199 页，859 个公式块（`rerun_w4/`） | 吞吐基准 + 稳定性验证 |
| 参数 A/B | 32/1、4/2、2/2 各 22~24 页 | 同一本书片段 | 选型依据，见 `性能与硬件.md` |

## 二、逐块对比（859 块，同一批页）

| 指标 | 旧（32/1） | 新（4/2） |
|---|---|---|
| 两侧都有分数 | — | 668 块 |
| 分数平均差 | — | **0.0000** |
| 分数中位差 | — | **0.0000** |
| 95 分位绝对差 | — | **0.0006** |
| 差值 > 0.05 的块 | — | **0 块** |
| 中位分数 | 0.8998 | 0.8998 |
| p10 / p90 | 0.1319 / 0.9684 | 0.1379 / 0.9684 |
| OK / CHECK / RENDER_FAIL / SCORE_ERR | 563 / 147 / 122 / 27 | 545 / 140 / 120 / 54 |

**结论**：并发参数**不改变打分结果**（95% 的块差值 ≤0.0006）。53 块的判定差异几乎全部是
jev 偶发 500（27 → 54），不是 OCR 或渲染变差。做 A/B 时先把 `SCORE_ERR` 剔掉或重试，否则会把服务抖动算成参数差异。

## 三、吞吐（新参数，全量 199 页）

| 阶段 | 耗时 | 占比 | 折算 |
|---|---|---|---|
| 解析 | 3,865s | 72% | 19.4s/页；59.1 布局块/分 |
| 复核 | 1,480s | 28% | 2.16s/块 |
| **合计** | **5,345s ≈ 89 分钟** | — | **42.7 布局块/分；9.7 公式块/分** |

⚠ **口径提醒**：常说「42 块/分」指的是**布局块**（含正文），公式块只有 9.7 块/分。
按公式块算，1000 块 ≈ 103 分钟，不是 24 分钟。

## 四、100 块人工标注要多久

| 步骤 | 谁做 | 工时 |
|---|---|---|
| 生成标注表（分层抽样 + 裁块图 + LaTeX + 页码） | 我做 | 约 15 分钟 |
| 单人判读 100 块（对图判对/错，错则备注） | 你 | 每块 30~45 秒 → **50~75 分钟** |
| 双人判读 + 冲突仲裁 | 你 + 一位同事 | 约 **2.5~3.5 小时**总工时 |

单人也够用：100 块里预计 15~20 块是 CHECK/未打分，判读成本主要花在这部分。
**前提是先剔除 SCORE_ERR**，否则 6~8% 的块需要重打分才能判。

## 五、时间都花在哪（从 10 本 + 我的 199 页里对账）

| 环节 | 实测耗时 | 占比 | 性质 |
|---|---|---|---|
| 版面检测（PP-DocLayout，CPU） | 4.5s/页 → 895s | 17% | CPU 单线程，与并发无关 |
| OCR 模型推理 | 约 2,970s | 55% | GPU，受 workers/np 影响 |
| 每本模型切换（OCR ↔ jev） | 约 11 分钟 | 12% | 34 本 × 2 次 × ~10s |
| 公式复核（xelatex 1.5s + jev 0.4s） | 1,480s | 28% | xelatex 串行在 CPU |
| 失败重试 / 500 | 未单独计时，体现为 54 个 SCORE_ERR | — | 服务抖动 |

**真正的两个大头**：OCR 推理（55%）与复核（28%，其中 xelatex 串行占大头）。

## 六、外部技术在做什么（调研）

| 方案 | 是什么 | 对本项目的意义 |
|---|---|---|
| [DocLayout-YOLO](https://arxiv.org/abs/2410.12628) | YOLOv10 骨干的版面检测，论文称比 PP-DocLayout 更快更准 | 版面检测占 17%，换模型可省一半以上；但 SDK 目前只吃 PP-DocLayoutV3，需要单独跑模型再喂 bbox |
| [MinerU](https://opendatalab.github.io/MinerU/zh/) | 文档解析流水线（版面 + OCR + 公式），工程化成熟 | 可对照它的批处理/并发设计；不建议直接替换现有链路 |
| llama.cpp prompt cache / checkpoint | 已在本机生效（cached n_tokens 0→2000+） | 已吃到，无需再动 |

**我的判断**：先别换模型。版面检测虽然占 17%，但换模型要重做 bbox 对接、重跑回归，
ROI 不如下面三件小事。

## 七、能自己改的，按 ROI 排序

| # | 改进 | 预期收益 | 风险 |
|---|---|---|---|
| 1 | ✅ **jev 500 降分辨率重试**（已实现） | 实测 12 个 SCORE_ERR：1200px 救回 5 个、**800px 救回 9 个（75%）**；人工复核量随之下降 | 低；只多一次失败重试 |
| 2 | ✅ **复核阶段并行**（`--qc-workers 4`，已实现） | 94 块实测：**692s → 197s（3.5×）**；全量复核 1480s 预计降到 450~600s | 低；渲染互不依赖 |
| 2b | ✅ **渲染结果缓存**（按 LaTeX 哈希，已实现） | 重复跑同一批块时省掉 xelatex；29 块实测 80s → 71s（轻量书约 -11%，重公式书更多） | 低；缓存目录三级回退 |
| 3 | **按阶段批处理**（先解析完所有书，再统一复核） | 省掉 34 次模型切换，约 -12% | 低；但断点粒度变粗 |
| 4 | 版面检测改 GPU 或 DocLayout-YOLO | -8~12% | 中；要重做 bbox 对接与回归 |
| 5 | 降低页图长边（8157→6000） | -10% 左右 | **高**；改变口径，分数不可比 |

前三条都不改变识别口径，加起来能省 **20~25%**，且都能用现有 199 页数据回归验证。

## 八、数学能插手的五个点（附本机验证）

链路本身没有「一招 10 倍」的奇迹：下限由 GPU 解码 + 版面检测 + xelatex 决定，每层优化 10~30%，
乘起来也到不了 10 倍。但有几处**确实该用数学**，按可落地程度排：

### 8.1 选择性验证（序贯决策）——已用现有数据验证

思路：不用 jev 打全部块，先用廉价特征判断「像不像 OK」，像的跳过打分。
代价是可能漏掉 CHECK。用 539 块（OK 435 / CHECK 104）做伪标签实测：

| 单特征 | AUC |
|---|---|
| LaTeX 长度 | 0.735 |
| 命令数 | 0.702 |
| 行数 / array | 0.605 / 0.604 |

`长度 − 0.5×命令数` 组合 AUC = **0.741**。按这个分数从「最像 OK」的一端跳过：

| 跳过比例 | 漏掉的 CHECK |
|---|---|
| 20% | 3 / 104 = 2.9% |
| 30% | 9 / 104 = 8.7% |
| 40% | 17 / 104 = 16.3% |

**可落地**：跳过 20% 的 jev 调用、只漏 3% 的可疑块，QC 成本降两成。若加入 OCR 的 token 对数概率
（现在没落盘）与编译结果，AUC 还能往上走。

### 8.2 保形预测定阈值（需要 100 块标签）

现在的 0.6 是拍的。用 split-conformal：在标注集上取分数分位数，使得「被放行的块中错的比例 ≤ ε」
具有有限样本保证。这是把阈值从经验值换成**可宣称的风险上界**。

### 8.3 多尺度分数融合（方差缩减）

边界块（0.4~0.7）用两个分辨率各打一次分再平均，能把「因缩图偶然掉分」的抖动压下去。
代价只发生在边界块（约 10%），收益是 CHECK 翻转变少。降分辨率重试的 9/12 救回率就是这个现象的证据。

### 8.4 排队论定并发

把 jev/OCR 请求看成 M/M/c，服务时间均值 μ、到达率 λ，最优槽位满足利用率 ρ≈0.8。
np=2 的实测最优（42 块/分）与 np=3 反慢（31）正好落在「多槽摊薄推测解码」的拐点上——
经验结论与排队模型一致，说明这组参数不是碰巧。

### 8.5 分辨率-精度权衡

页图长边 8157 是拍的。按笔画宽度分布估最小可辨分辨率（每笔画 ≥2px），部分扫描件可降到 5000 左右，
解析与版面检测都按像素线性下降。**风险是改变口径，分数不可比**，只能对确认笔画粗的书单独降。

### 8.6 抽样设计

1000 块用随机页抽样，方差大（前面 199 页只出 859 块、密度 1.9~12 块/页）。
按书分层 + 按页整群抽样能把同样置信区间的页数降 20~30%，等于省时间。
